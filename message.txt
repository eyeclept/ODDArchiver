Disc read recovery

DiscBackend.append() auto-recovers growisofs -M append failures. These failures happen because of stale kernel block-device cache on USB-bridged BD-R drives.

The fix writes to the drive's USB authorized file. Then it waits for the device node to reappear. After that, the system retries growisofs -M.

A standalone oddarchiver/usb_reauth.py helper performs the USB re-enumeration. It uses only stdlib. Install it once as a root-owned system binary.

DiscBackend.read_path() also recognizes automount busy-device errors. When it sees these errors, it unmounts and retries.

Progress bar

_run_growisofs() now streams growisofs output live. It collapses the xorriso percent-done/ETA line into the existing in-place progress bar. The progress bar uses the same style as session._print_bar.

Non-progress lines still print through unchanged. These lines include errors, Executing, flushing cache, and closing track.

Staging collision fix

A real production incident happened with a partially zero-filled disc. Test runs collided with a live burn through the shared staging directory.

The fix adds a per-test autouse fixture. This fixture overrides XDG_RUNTIME_DIR to tmp_path. It also adds a PID lockfile in the staging directory. It adds a source-scan exclusion for the staging path.

Documentation

README.md and SETUP.md now document the staging-space check failure. They also document the explicit xorriso dependency. They document the USB re-enumeration recovery procedure.

Tests

The full test suite grew from 155 to 186 tests. All tests pass.
